# 道場打刻システム 改修計画（Supabase + Vercel 移行）

この文書は、Claude CLI や Codex に実装を依頼するための計画書です。現在の仕組み（Google スプレッドシート + Apps Script + GitHub Pages）を、**Supabase（データベース・認証）+ Vercel（アプリの公開）**に移します。

- 現行の実装は `legacy/` にあります（`legacy/Code.gs`、`legacy/index.html`、`legacy/README.md`）。**業務ルールの正解は現行コード**です。迷ったら `legacy/Code.gs` の動きに合わせてください。
- 開発ルールは `AGENTS.md` を参照してください。

---

## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 目的 | アプリを速くする（現行は1操作に数秒かかる）。コードを分けてテストで守り、保守しやすくする |
| 利用者 | 島根大学弓道部の部員 60〜80名。主将が管理し、罰は副務が扱う |
| 費用 | 0円で運用する（Supabase 無料プラン、Vercel Hobby プラン） |
| 公開 | Vercel（プルリクエストごとに確認用URLが出る） |
| 現在の利用状況 | 確認用に開発者1人がログインしているだけ。**本番データの移行は不要**（ルール・設定だけ引き継ぐ） |

### 遅い原因（現行）
1. Apps Script の1回の呼び出し自体に1〜2秒かかる。
2. 画面を開くたびの `status` で、ほぼ全シート（名簿・コマ表・臨時変更・ルール・罰・割り当て・打刻ログ最大3000行・設定）を読み直している。
3. 打刻のたびに在室状況シートを書き直し、遅刻なら全員分を再判定し、そのあとアプリが `status` を取り直す。

### 性能の目標
| 操作 | 目標 |
|---|---|
| アプリを開いてから画面が出るまで | 0.5秒以内（前回の内容を先に表示し、裏で更新） |
| QRを読んでから結果が出るまで | 1秒以内（4G回線） |
| 在室一覧の更新 | 打刻から数秒以内に、開いている全員の画面に反映（Realtime） |

## 2. 現行の業務ルール（移行で変えないこと）

### 2.1 練習日と遅刻の基準
| 曜日 | 条件 | 区分 | 遅刻基準（集合） | 練習開始 |
|---|---|---|---|---|
| 月・火・木 | 4・5コマなし | 前半 | 17:00 | 17:30 |
| 月・火・木 | 4コマあり | 前半 | 17:30 | 17:30 |
| 月・火・木 | 5コマあり | 後半 | 19:15 | 19:45 |
| 土 | 全員 | 全体 | 08:20 | 09:15 |

- 4コマ・5コマの有無は、部員ごとの**コマ表**（月4・月5・火4・火5・木4・木5）で決まる。5コマありなら後半、4コマのみなら前半17:30、どちらもなければ前半17:00。
- 選考期間も同じルール。ルールは管理画面で変更できること（現行は「練習ルール」シート）。
- その日の**最初の入室**が集合時刻を1秒でも過ぎたら遅刻。遅刻の分数は切り上げ。

### 2.2 臨時変更（その日だけの例外）
| 内容 | 対象 | 意味 |
|---|---|---|
| 休み | 全員（学生番号空欄）または個人 | 全員なら練習日ではなくなる。個人なら「対象外」 |
| 4・5コマなし／4コマあり／5コマあり | 全員または個人 | その日のコマ表を上書き（休講・補講）。「4・5コマなし」を先に適用し、そのあと「あり」を適用 |
| 欠席連絡済／遅刻連絡済 | 個人 | 主将への連絡。**連絡日時**を記録する。部員がアプリから送るか、電話や LINE で受けた主将が入力する（2.3.1） |
| 参加 | 個人 | 引退した人の参加登録（2.5） |

### 2.3 判定（出欠一覧）
| 判定 | 条件 | 罰 |
|---|---|---|
| 出席 | 集合時刻までに入室 | なし |
| 遅刻 | 遅れて入室し、連絡なし | あり |
| 遅刻（連絡済） | 遅れて入室し、締め切りまでに連絡あり | なし |
| 遅刻（連絡遅れ） | 遅れて入室し、連絡が締め切り後 | あり |
| 無断欠席 | 入室なし・連絡なし（自動退室時刻を過ぎて確定） | あり |
| 欠席（連絡済） | 入室なし・締め切りまでに欠席連絡 | なし |
| 欠席（連絡遅れ） | 入室なし・欠席連絡が締め切り後 | あり |
| 遅刻（承認待ち） | 遅れて入室し、締め切りまでの連絡が承認待ち | なし（承認か却下まで保留） |
| 欠席（承認待ち） | 入室なし・締め切りまでの連絡が承認待ち | なし（承認か却下まで保留） |
| 未到着 | 自動退室時刻前でまだ来ていない（当日と先の日付） | なし（夜に確定） |
| 対象外 | 個人の「休み」 | なし |
| 参加（登録なし） | 引退した人が参加登録なしで来た | なし |

- **連絡の締め切り**＝集合時刻の60分前（設定で変更可）。連絡日時が空欄なら締め切り内として扱い、備考に残す。
- 遅刻連絡済で、実際には来なかった場合は欠席として扱う（現行の `judgeDate` を参照）。
- 主将は判定を**手動判定**で上書きできる（修正理由は必須）。最終判定＝手動判定があればそれ、なければ自動判定。上書きした時点で、その人の自動の罰を最終判定に合わせる（自動判定は計算し直さない）。
- 臨時変更を足しただけでは、出欠は変わらない（現行と同じ）。当日分は夜の判定で、過去の日は「この日を判定し直す」で反映する。
- 遅刻の罰は**打刻した時点で**つける。無断欠席・欠席（連絡遅れ）は**夜の判定**でつける。
- 入室を取り消したら、その日を判定し直し、遅刻の罰を外す。
- 現行と変えた点：現行は先の日付を判定すると全員が無断欠席になる。新アプリでは、自動退室時刻を過ぎるまで欠席を確定しない（欠席の連絡がある人は、現行と同じくすぐ「欠席」になる）。
- 現行と変えた点：現行は判定し直すと、休部・退部・卒業になった部員の過去の行と罰が消える。新アプリでは、判定の対象でない部員の記録には触れない。

#### 2.3.1 アプリからの欠席・遅刻の連絡（2026-11-27 追加）
現行は、部員が LINE などで主将に連絡し、主将が臨時変更シートに入力する。新アプリでは、部員がアプリからも送れる。当面は LINE と併用する。

- 送れるのは承認済みの現役と、その日の参加を登録した引退した人。今日から14日先までの練習日。**理由は必須**（200文字まで）。早退の連絡はない。
- **締め切りまでの連絡は「承認待ち」**になり、主将か管理者が承認・却下する（副務は見るだけ）。
  - 承認：連絡済（罰なし）。
  - 却下：**連絡がないのと同じ**（無断欠席か遅刻で罰）。却下の理由は任意で、本人に表示する。判断はあとから変えられる。
  - どちらもしないうちは、練習日を過ぎても**罰をつけない**。
- **締め切り後の連絡**も受け付けるが、承認の対象にせず「連絡遅れ」にする（罰あり）。
- 取り消しと出し直しは締め切りまで。そのあとは主将が直す。主将が入力した連絡は、本人は変えられない。今日の入室を記録したあとは、今日の連絡を送れない。
- **却下が練習日より後になったとき**につく罰は、倍になる日数を**却下した日から**数える（主将の確認を待っていた分、罰が増えないように）。罰の日付は練習日のまま。
- 承認・却下したとき、今日までの日はその人だけを判定し直す。**過去の日は、出欠一覧に記録した区分と集合時刻のまま**判定する（あとから変えたコマ表の影響を受けない）。手動判定は残る。
- 理由を読めるのは、本人・主将・副務・管理者だけ。
- 送っただけでは出欠一覧を変えない。入室したときか、夜の処理で判定する。

#### 2.3.2 コマ変更の申請（2026-11-27 追加）
休講・補講で集合時刻が変わるとき、部員がアプリから申請する。全員向けの休講などは、これまでどおり主将が臨時変更に入力する。

- 申請できるのは、コマで集合時刻が変わる日（月・火・木）の、今日から14日先まで。内容は「4・5コマなし／4コマのみ／5コマあり」から今の予定と違うもの。**理由は必須**。
- **承認制**（主将か管理者）。締め切りは**変更前の**集合の60分前で、過ぎた申請は受け付けない（主将に直接伝える）。締め切りまでは出し直しと取り消しができる。
- 承認したら、その日は申請の内容で判定する（コマ表と、主将が入力した臨時変更より優先）。却下したら、申請がないのと同じ。
- **承認待ちの間**は、遅刻・欠席になる場合の罰を保留する。
- 過去の日をあとから承認・却下したときは、承認なら申請の時刻、却下なら申請時に記録した変更前の時刻で判定する。ついた罰は、確認した日から数える。

### 2.4 罰
- 自動でつく理由：遅刻、遅刻（連絡遅れ）、無断欠席、欠席（連絡遅れ）。
- 副務がつける理由：私物の出しっぱなし、その他（メモ必須）。理由と「基本の数」は管理画面で増やせる（初期値はすべて1個）。
- **残りの数**：基本の数から始まり、ついた日から7日ごとに残りが2倍（1→2→4→8…）。倍になる日の**前日まで**に消化した分は、倍にする前に差し引く。計算は `legacy/Code.gs` の `computePenalty_` と同じ結果になること。
  - 例：1個の罰が8日目に2個になり、9日目に1個消化すると残り1個。14日目に残り1個が2倍になって2個。
- **やること**：罰1個につき1つ、副務が内容（自由記述。例：的貼り3個、道場の掃除）を割り当てる。部員は自分のやることをアプリで確認する。
  - 副務がつける罰は、つけるときに**基本の数ぶん**のやることを必ず入力する。
  - 自動の罰は、あとから「割り当てる」。倍になって増えた分も同じように割り当てる。
- **消化**：部員が証拠の画像を副務に送り、副務がアプリでそのやることを「消化済み」にする（2回押して確定）。やること1つ＝罰1個の消化。
- 判定が変わっても、**消化済みの罰と、やることを割り当て済みの罰は消さない**（副務が見直す）。
- 現行と変えた点（2026-11-28）：罰を扱う（つける・割り当てる・変更・消化・取り消す）のは**副務と管理者だけ**で、**主将は扱わない**（見るだけ）。罰の種類と倍になる日数の設定は、これまでどおり主将と管理者が変える。
- 現行と変えた点（2026-11-28）：**自分の罰は消化も取り消しもできない**。ほかの副務に依頼する。管理者は除く。
- **つけ間違いの取り消し**：まだ1個も消化していない罰は、副務（本人を除く）か管理者が取り消せる。記録は残り（取り消した日時と人）、自動の罰は判定し直してもつけ直さない。現行の「罰一覧の消化済みチェックでまるごと消す」操作は設けない。
- 主将が出欠の手動判定や連絡の承認をすると、その結果に合わせて自動の罰がつくか外れる（手を付けていない罰だけ）。部員を削除すると、その人の罰も消える。
- 現行と変えた点：現行は、やることを割り当てた罰がある日を判定し直すと、同じ罰がもう1件できる。新アプリでは、1人につき1日1件（`auto_key` が一意）とし、割り当て済みの罰があれば追加しない。
- 全員が全員分の未消化の罰を見られる（日付の古い順）。統計用に記録はすべて残す。

#### 2.4.1 罰の集計（2026-11-28 追加）
- 役職タブの「集計」で、期間を指定して罰の統計を見る。見られるのは**主将・副務・管理者**（部員ごとの数が分かるため、部員には出さない）。
- 期間は、今月（1日から今日まで）、先月、今年度（4月1日から今日まで）、日付の指定（10年以内）。
- **つけた数**：期間内の日付の罰の基本の数。**消化した数**：期間内に消化した数（期間より前の罰の分も含む）。**いまの残り**：期間に関係なく今日の残り（倍になった分を含む）。取り消した罰は数えない。倍になって増えた数だけの集計は出さない。
- 画面は統計資料の形（白地、図表の番号と題、単位、末尾の注）。上に期間の選択と**表1 概況**を置き、下を「推移」「理由」「部員」で切り替える。
  - 概況：つけた・消化した・残りと、比べる期間との差。比べる期間は、今月なら前月の同じ日まで（その月にない日は末日まで）、先月なら先々月、今年度なら前年度の同じ日まで、日付の指定なら直前の同じ日数。比べる期間の終わりまでに記録が1件もなければ「―」。残りは比べない。
  - 推移（図1）：棒（区切りが8つまでは棒の上に数）・折れ線・累計を選ぶ。14日以内は日ごと、100日以内は月曜始まりの週ごと、それより長ければ月ごと。同じ数の表を下に常に出す。
  - 理由（表2）：つけた数と割合。
  - 部員（表3）：つけた・消化・残りを1つの表に出し、見出しを押した数の多い順に並べる（同じ数は同じ順位）。はじめは10人。名前を押すと罰の内訳。
- 新しいアプリの記録だけが対象。部員を削除すると、その人の分は集計からも消える。
- 項目を増やすとき（的中率、選考の順位など）：集計は `packages/core/src/<項目>-stats.ts`、画面は `apps/web/src/features/stats/<項目>/` に置き、`StatsSection` で切り替える。期間と区切り・比べる期間・順位（`core/stats.ts`）、期間の指定・順位の表・グラフの部品（`features/stats/`）は共通で使う。記録を持つ表と、書き込みの Edge Functions は項目ごとに足す。

### 2.5 引退した人（参加連絡制）
- 部員の**状態**：現役／引退／休部・退部／卒業。判定は学年ではなく状態で決まる。
- 現役：毎回判定。引退：**参加を登録した日だけ**判定（来なければ無断欠席、遅れたら遅刻の罰）。登録していない日は来ても判定しない。
- 参加の登録は**集合時刻まで**、取り消しは**連絡の締め切り（集合の60分前）まで**。登録できるのは今日から14日先まで。
- 引退日より前の日は現役として判定する。引退しても残っている罰はそのまま。
- 休部・退部・卒業：打刻できず、判定もしない。

### 2.6 代替わり・年度替わり
- **代替わり**（10月ごろ）：引退する学年の現役部員を一括で「引退」にし、引退日を記録。新しい主将・副務を指定すると役職を入れ替え、引退する人の役職は外す。
- **学年の繰り上げ**（4月）：1→2→3→4年、院1→院2年。4年・院2年は「卒業」。現役・引退の状態は変えない。年1回だけ実行（二重実行を防ぐこと）。
- 現行と変えた点：名簿の変更、再登録の許可、代替わり、学年の繰り上げは、承認済みで在籍中かつ端末が結びついた主将が1人も残らない場合は実行しない（アプリから管理できなくなるため）。

### 2.7 打刻
- 入口に貼った QR（中身は現行の設定シートの値。**印刷済みなので変えない**。公開リポジトリなので値も画像も置かない）を読む。在室中なら退室、そうでなければ入室。
- 位置チェック：道場の緯度・経度が設定されていれば、距離 − GPS誤差（最大200m）が許容距離（初期150m）以内のときだけ受け付ける。
- 直前の打刻から120秒以内の読み取りは無視（二重読み取り）。打刻後60秒以内なら本人が取り消せる。
- 毎晩22:00に、在室中の人を**自動退室**にする（備考に「退室打刻なし」）。そのあと当日を判定する。22:00より後に入室した人の自動退室は、入室と同じ時刻にする（現行は22:00）。
- 在室一覧（いま道場にいる人と入室時刻）を全員が見られる。

### 2.7.1 参加者と立ち順（2026-11-27 追加）
現行は、主将が名前の木札を並べ替えて決めている。アプリは、その日の参加者を出して、木札と同じように並べられるようにする。

- **参加者**：現役は欠席の連絡がなければ参加。引退した人は参加を登録した人だけ。休部・退部・卒業と、個人の「休み」は入れない。却下した連絡は使わない。区分（前半・後半・全体）ごとに分けて、板も別に作る。平日は参加者がいなくても前半と後半の両方を出す。区分はコマ表と臨時変更で決まる。
- **並べ方**は2つ。**的割り**（平日の通常練習。9的を右端から大前・2的〜7的・落前・落。列の中は上から引く順）と、**立ち**（土曜、強化練習の平日・土曜、選考の日。1立ち8人まで。人数のきりが悪いときは「9人まで」を選び、9的で運用する。右端が大前で、**何人の立ちでも最後の2人が落前と落**。間は2的、3的…。2人なら大前と落）。男女は分けない。
- 手で直すときは、札を長押ししてドラッグする。**札の中央に置くと入れ替え、札と札の境目に置くと間に入れて後ろをずらす**（人数がいっぱいの立ちにほかから入れるときは入れ替え）。列の最後や置き場にも移せる。押してから移し先を押しても直せる。保存する前の操作は「戻す」で1つずつ戻せる。
- **自動で並べる**：学年の上の人から均等に配り、遅刻者は列の後ろ（立ちでは後の立ち）にする。
- **分ける役職**：主将・男子副将・女子副将・主務は互いに別の列。副務どうしも別の列（副務と前の4人は同じ列でよい）。会計は分けない。立ちが足りなければ増やす。手で同じ列にした場合は、注意を出すだけで止めない。
- 作れるのは**主将・男子副将・女子副将・主務と管理者**（2026-11-28 に4役へ広げた。主将が出ない区分の立ち順を、ほかの3役が作れるように）で、**当日分だけ**。どの区分も触れる。男子副将・女子副将・主務には参加・遅刻・欠席の状態だけを渡し、連絡の理由は渡さない。
- 保存していない内容は端末に残す。**ほかの人が先に保存や削除をしていたら上書きせず**、知らせて、どちらを残すか選んでもらう。最後に保存した人と時刻を出す。公開すると承認済みの部員が打刻画面で見られる（自分の札を強調し、的割りでは「あなたは 2的」、立ちでは「あなたは 1立ち目の5番目」と出す。遅刻の印は出さない）。公開しなくてもよい。翌日の夜の処理で消し、過去分は残さない。

### 2.7.2 通知（2026-11-27 追加）
- Web Push（追加の料金なし）。iPhone は iOS 16.4 以降で、ホーム画面に追加して開いた場合だけ受け取れる。端末ごとに「自分」タブでオンにする。
- 連絡・申請と、新しい部員の登録が届いたら主将と管理者へ（送った本人は除く）。承認・却下したら本人へ。立ち順の公開は知らせない。副務には通知しない。
- 通知を押すと、連絡の一覧、名簿、打刻の画面のうち該当するものを開く。
- ロック画面に出るので、**理由は通知に入れない**（名前・日付・種類だけ）。
- 送れなくても、元の操作は成功にする。使えなくなった届け先は消す。

### 2.8 部員登録と役職
- 部員がアプリで登録する（学生番号・名前・性別 男/女・学年 1〜4年/院1〜2年）。続けてコマ表を入力する。
- **主将が承認するまで打刻できない**。承認していない人は判定にも載らない。
- 役職：部員／主将／副務（ほかの役職は下の「現行と変えた点」）。罰を扱うのは副務と管理者（2.4）。承認・名簿・臨時変更・手動判定・設定・代替わりは主将と管理者。
- スマホを替えたときは、主将が「再登録を許可」すると、同じ学生番号で登録し直せる（承認はやり直し）。
- 現行と変えた点：主将と管理者は、部員を**削除**できる。本人の打刻・出欠・罰・臨時変更・コマ表も消え、元に戻せない（本人が記録した他人の記録は残し、記録した人を空にする）。自分は削除できない。退部した人の記録を残すときは、削除せず状態を「休部・退部」にする。
- 現行と変えた点：開発用に**管理者ログイン**（部員ではないログイン）を追加した。主将と同じ管理操作と、罰の操作ができる。打刻・出欠・罰の対象にはならない。本番では登録しない。
- 現行と変えた点：役職に**管理者**を追加した（アプリを管理する人が、主将と表示されずに済むように）。部員のまま打刻・判定の対象になり、主将と同じ管理操作と罰の操作ができる。この役職の付け外しと、管理者の部員の変更（承認・名簿・再登録の許可・削除）は、管理者（この役職の部員か管理者ログイン）だけができる。代替わりで引退しても役職は残る。卒業・休部・退部にすると操作できなくなる。管理できる人（主将か管理者）が1人もいなくなる変更はできない。
- 現行と変えた点：役職に**男子副将・女子副将・主務・会計**を追加した（2026-11-27）。権限は部員と同じで、役職は1人1つ（2026-11-28 から、男子副将・女子副将・主務は立ち順を作れる）。代替わりで引退すると外れる。新しい人は名簿で指定する。
- コマ表は設定で「ロック」でき、ロック中は部員が変更できない。

## 3. 目標の構成

```
部員のスマホ（PWA）
   │  supabase-js（読み取りは直接、書き込みは Edge Functions 経由）
   ▼
Vercel（静的配信） ── アプリ本体（Vite + React + TypeScript）
Supabase
   ├─ Postgres（データ。RLS で権限を守る）
   ├─ Auth（匿名ログイン。端末ごとのセッション）
   ├─ Edge Functions（書き込み・業務ロジック。TypeScript）
   ├─ Realtime（在室一覧の更新）
   └─ pg_cron + pg_net（毎晩の自動退室・判定）
```

### 方針
- **業務ロジックは `packages/core` の純粋な関数**にまとめる（DB・画面に触れない）。Edge Functions と画面の両方から使い、Vitest でテストする。
  - 例：その日の区分と集合時刻を決める、遅刻の分数、判定、連絡が締め切り内か、罰の残りの数、参加登録の可否。
- **読み取り**はアプリから直接（RLS で制限）。ホーム画面に必要なものは**1回の問い合わせ**で取れるようにする（ビューまたは RPC）。
- **書き込み**は Edge Functions を通す。権限確認・業務ルールの適用・複数テーブルの更新をサーバー側で行う（アプリから表を直接書き換えない）。
- 日付と時刻は**日本時間（Asia/Tokyo）**で扱う。DB には `timestamptz` で保存し、「練習日」は日本時間の日付（`date`）で持つ。

### リポジトリ構成（案）
```
kyudo-dakoku/
├─ apps/
│  └─ web/                 アプリ（Vite + React + TypeScript、PWA）
│     ├─ src/features/     scan / presence / penalties / profile / admin（画面ごと）
│     ├─ src/lib/          supabase クライアント、API 呼び出し、キャッシュ
│     └─ src/styles/       CSS（インラインスタイルは使わない）
```

## 5. 認証と権限

- **匿名ログイン（Supabase Anonymous Sign-in）**を使う。初回にアプリが匿名ユーザーを作り、部員登録でその `auth.uid()` を `members.auth_user_id` に結びつける。端末にセッションが残るので、以後は入力なしで使える（現行の識別キーと同じ考え方）。
  - iPhone は Safari とホーム画面のアプリで保存場所が別なので、「先にホーム画面に追加してから登録」の案内を残す。
  - **LINE などのアプリの中のブラウザでは登録させない**（保存場所が別で、あとで未登録になるため）。いつものブラウザへ案内する。部員に送るリンクには `?openExternalBrowser=1` をつける。iPhone のブラウザでは、先にホーム画面に追加する手順を出す（2026-11-28）。
  - **引き継ぎ番号**（2026-11-28 追加）：登録済みの画面の「自分」タブで6桁の番号を出し、移し先で学生番号と一緒に入力すると、登録が移る。承認はそのままで、元の画面は未登録になる（1人1台のまま）。番号は10分間・1回だけ使え、5回まちがえると無効になる。番号はそのまま保存せず、ハッシュだけを持つ。
  - 登録済みの画面を開けないときは、主将が `auth_user_id` を外す（「再登録を許可」）→ 本人が同じ学生番号で登録し直す → 再承認。
- **RLS（行単位の権限）**
  - 承認済みの部員は、全員の名前・在室・未消化の罰とやることを読める（全員が全員分の罰を見る運用のため）。
  - コマ表・臨時変更（連絡日時）・打刻の詳細・出欠一覧・部員名簿の行は、本人と主将・副務だけが読める。全員向けの臨時変更は登録した部員が読める。
  - 立ち順を作る4役は、関数 `lineup_day()` で今日の参加者を決める材料（理由を除く）と保存した立ち順を読む。
  - 入口QRの設定は主将だけが読める。ほかの設定と練習ルールは登録した部員が読める。
  - ほかの部員の名前は、承認済みの部員だけが呼べるデータベース関数で返す。
  - 書き込みはすべて Edge Functions（service role）経由。表への直接の insert/update/delete は許可しない。
- Edge Functions は毎回、呼び出した人の `members` 行を引き、**状態・承認・役職**を確認してから処理する。
- **管理者**（開発用）は、メールアドレスとパスワードでログインし、`admins` 表に登録されたアカウント。表への登録は SQL でだけ行う。主将が読めるものをすべて読め、管理操作と罰の操作ができる。「主将がいなくなる変更はできない」という制限は受けない（唯一の主将の再登録を許可できるように）。アプリは管理者のログインを部員のログインとは別に保存するので、部員登録した端末で使っても登録は消えない。
- 書き込みはデータベースに直接つなぎ、1つの操作を1つのトランザクションにする。同じ部員の打刻と判定は、部員の行をロックして順に処理する。
- ホーム画面は関数 `home()`、在室一覧は `presence()`、未消化の罰は `penalty_board()` で読む。

## 6. Edge Functions（書き込み）一覧

起動の待ち時間（コールドスタート）を減らすため、アプリからの操作は1つの関数 `api` にまとめ、本文の `action` で選ぶ。下の表の名前は `action` の値。`nightly` だけは別の関数にする。サーバー側の処理は `supabase/functions/_shared/` に置き、ローカルの DB を使ってテストする。

| 関数 | 誰が | 内容 |
|---|---|---|
| `register` | 未登録の人 | 学生番号・名前・性別・学年で登録（承認待ち）。既存の学生番号で `auth_user_id` が空なら引き継ぐ |
| `create-transfer-code` | 登録した端末 | 引き継ぎ番号を出す（5章） |
| `claim-transfer` | 未登録の端末 | 学生番号と引き継ぎ番号で、登録を移す |
| `set-koma` | 本人 | コマ表の保存（ロック中は拒否） |
| `scan` | 承認済み・現役／引退 | QR・位置の確認 → 二重読み取りの無視 → 入室/退室 → 初回入室なら判定し、遅刻なら罰をつける。**最新の在室・判定・罰の数を返す**（アプリが取り直さなくて済むように） |
| `undo-scan` | 本人 | 60秒以内の取り消し。入室の取り消しならその日を判定し直す |
| `join` / `unjoin` | 引退した人 | 参加の登録・取り消し（2.5 の締め切り） |
| `submit-notice` / `cancel-notice` | 承認済み・現役／参加を登録した引退した人 | 欠席・遅刻の連絡の送信・取り消し（2.3.1） |
| `admin-review-notice` | 主将 | 連絡とコマ変更の申請の承認・却下 |
| `submit-koma-change` / `cancel-koma-change` | 承認済み・現役／参加を登録した引退した人 | コマ変更の申請・取り消し（2.3.2） |
| `admin-save-lineup` / `admin-delete-lineup` | 4役・管理者 | 当日の立ち順の保存・削除（2.7.1） |
| `push-config` / `push-subscribe` / `push-unsubscribe` | 登録した端末・管理者 | 通知の鍵の取得、届け先の登録・解除（2.7.2） |
| `add-penalty` | 副務・管理者 | 罰をつける（基本の数ぶんのやることが必須） |
| `assign-task` / `edit-task` / `complete-task` | 副務・管理者 | やることの割り当て・変更・消化（自分の罰は消化できない。管理者は除く） |
| `cancel-penalty` | 副務・管理者 | つけ間違いの取り消し（2.4） |
| `admin-*` | 主将 | 承認、部員の削除、再登録の許可、名前・状態・役職・学年・引退日の変更、臨時変更の登録と削除（連絡日時つき）、手動判定、指定日の再判定、設定・練習ルール・罰の種類の変更。入口QRは画面から変えられない |
| `change-generation` | 主将 | 代替わり（2.6） |
| `promote-grades` | 主将 | 学年の繰り上げ（2.6。年度ごとに1回だけ） |
| `nightly` | pg_cron | 自動退室 → 当日の判定（無断欠席などの罰） |

- 判定（`judge(date)`）は1か所に実装し、`scan`・`undo-scan`・`admin-rejudge`・`nightly` から呼ぶ。遅刻の判定し直しは**その人の分だけ**で済ませる。
- 自動の罰を付け直すときは、2.4 の「消化済み・割り当て済みは消さない」を守る。

## 7. 画面

部員向けは現行と同じ4つのタブ（打刻・在室・罰・自分）。現行の `legacy/index.html` の見た目と文言を基本にする。

| タブ | 内容 |
|---|---|
| 打刻 | 今日の集合時刻と自分の罰の数、「欠席・遅刻を連絡する」（連絡の欄へ移る） → **QR読み取り**（今日の欄のすぐ下。次が入室か退室かを表示） → 結果（入室/退室・時刻・遅刻なら「罰がつきました」・取り消しボタン）とその下の「退室する／入室する（QRを読む）」ボタン → 今日の自分の入退室の記録 → 公開された今日の立ち順（自分の場所だけを大きく出し、板は開いて見る。自分が入っている区分が先） → これからの練習日（欠席・遅刻の連絡、コマ変更の申請と状態。引退した人は参加の登録も） |
| 在室 | いま道場にいる人と入室時刻（Realtime で自動更新） |
| 罰 | 自分の罰と、やること一覧。全員の未消化の罰（古い順、あと何日で2倍か）。副務と管理者は割り当て・変更・消化・取り消し・罰をつける |
| 自分 | 登録内容、コマ表の入力 |
| 役職（役職のある人だけ） | 副務は出欠の連絡の一覧（理由も表示。見るだけ）と罰の集計。男子副将・女子副将・主務は立ち順。主将と管理者は次の管理すべて：出欠の連絡とコマ変更の申請の承認・却下（連絡と部員の承認待ちの数をタブに表示）、今日の参加者と立ち順、承認待ちの部員、名簿（状態・役職・学年・再登録の許可）、臨時変更（休講・補講、欠席/遅刻連絡と連絡日時）、出欠一覧（手動判定・再判定）、罰の集計（2.4.1）、設定・練習ルール・罰の種類、代替わり、学年の繰り上げ、CSV 書き出し |

### 速さのための工夫
- 前回のホーム画面の内容を端末に保存し、開いた瞬間に表示して裏で更新する。
- 罰・在室・管理は、そのタブを開いたときに読み込む。
- QR 読み取りは、対応していればブラウザ標準の `BarcodeDetector` を使い、なければ jsQR（映像を縮小してから解析）。
- 位置情報は読み取りと並行して取得し、緯度・経度が未設定なら取得しない。
- PWA としてアプリ本体をキャッシュし、2回目以降の起動を速くする。

| 項目 | 方法 |
|---|---|
| 毎晩の処理 | pg_cron が15分ごとに `nightly` を呼び、自動退室の時刻の15分後（初期値 22:15）以降の最初の回に1日1回だけ実行する。失敗した場合は次の回にやり直す。自動退室の時刻は23:30まで。日付が変わって実行できなかった日は、主将が「この日を判定し直す」で判定する。呼び出し先は Vault の `nightly_url`、合言葉は `nightly_secret`（自動生成） |
| 無料プランの一時停止対策 | 7日間使われないと止まる。長期休み対策に、GitHub Actions で3日ごとに `ping()` を呼ぶ（Actions の変数に呼び出し先を設定する。公開リポジトリでは60日間更新がないと定期実行が止まるので注意）。毎晩の pg_cron だけで防げるかは要確認 |
| バックアップ | 無料プランは自動バックアップなし。管理画面の CSV 書き出しに加え、週1回 GitHub Actions で主要テーブルを書き出す（保存先は未決事項） |
| 秘密情報 | Supabase の service role キーは Edge Functions の環境変数だけに置く。アプリには anon キーだけ（RLS で守る）。リポジトリにキーを書かない。入口QRの中身も書かない |
| 公開 | Vercel をリポジトリにつなぐ。プルリクエストごとに確認用URL、main への反映で本番 |
| 確認用と本番の分離 | 確認用URLから本番 DB を触らないよう、Supabase は本番と開発の2プロジェクト（無料枠は2つまで）を使う |

## 9. 進め方（フェーズ）

各フェーズは小さなプルリクエストに分け、確認用URLで動作を確かめてから次に進む。

| フェーズ | 内容 | 終わりの条件 |
|---|---|---|
| P0 土台 | モノレポ（pnpm workspaces）、TypeScript strict、ESLint/Prettier、Vitest、GitHub Actions、Vercel 接続、Supabase CLI の初期化 | 空のアプリが確認用URLで開ける。CI が通る |
| P1 業務ロジック | `legacy/Code.gs` の判定・罰計算・参加登録の可否を `packages/core` に移植し、10章のテストを書く | テストがすべて通る |
| P2 データベース | 4章のテーブル、RLS、初期値のマイグレーション（練習ルール・罰の種類・設定）。`seed.sql` はローカル用の仮の入口QRだけ。現行の値は開発・本番の DB に直接入れる | 開発用プロジェクトにマイグレーションが通る。RLS のテスト（他人のコマ表が読めないなど） |
| P3 部員の機能 | 登録・承認待ち・コマ表・打刻・取り消し・在室・罰の閲覧・参加登録 | 実機（iPhone・Android）で登録→承認→打刻→在室表示が動く |
| P4 管理の機能 | 管理タブ一式、罰の付与・割り当て・消化 | 主将・副務の操作が現行と同じ結果になる（2.4 で変えた権限を除く） |
| P5 自動処理 | nightly（pg_cron）、Realtime、CSV 書き出し、停止対策 | 夜に自動退室と判定が動く |
| P6 切り替え | 本番プロジェクトを作り、設定を入れ、部員に新しいURLを案内。GitHub Pages を止め、Apps Script のウェブアプリを無効にする | 部員が新アプリで打刻できる |
