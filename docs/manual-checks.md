# 実機での確認（P3〜P5）

自動テストでは確かめられない項目です。**すべて済むまで、P3〜P5 は完了にしません。**
確認は開発用の Supabase（`kyudo-dakoku-dev`）につながった https://kyudo-dakoku.vercel.app で行います。部員には、まだ今までのアプリを使ってもらいます。

## 準備

1. README の「新しいアプリの初期設定」のうち、**入口QRの中身**を開発用プロジェクトに入れる（呼び出し先 `nightly_url` は設定済み）。
2. 同じ節の手順で**開発用の管理者**を作り、アプリの「管理者ログイン」から入る。主将は、部員登録してもらったあと役職タブで指定する。
3. GitHub の Actions の変数 `SUPABASE_URL`・`SUPABASE_PUBLISHABLE_KEY` を設定し、「Keep Supabase awake」を手動で実行して成功することを確かめる。

## 切り替え（P6）の前に必要なこと

- 匿名ログインは、同じ回線から1時間に30回までが初期値。部員が道場の Wi-Fi で一斉に登録する場合は、本番プロジェクトの **Authentication → Rate Limits** で上限を上げる。
- 本番プロジェクトを作り、マイグレーション、Edge Functions、README の初期設定の SQL（3つ）を適用する。
- Vercel の **Production** の環境変数と、GitHub の Actions の変数を本番の値に変える。
- 本番プロジェクトには開発用の管理者を作らない（`admins` 表は空のままにする）。
- バックアップの保存先を決める（計画書11章）。CSV の書き出し以外の自動バックアップはまだない。
